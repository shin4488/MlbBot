# ツイート内容の改善案

現状のツイートは地区ごとに以下の形式（毎日6件）。X APIは投稿ごとの従量課金（$0.015/件）のため、ツイート件数が増える案はコスト増とセットで判断する。

```
⚾ AL | East ⚾️ Win : Loss : Behind
1. Yankees      : 52 : 30 : 0
2. Red Sox      : 48 : 34 : 4
...
#MLB #RepBX #Yankees #DirtyWater #RedSox
```

## 1. 桁揃え（PadRight）は機能していないので廃止する

Xのタイムラインは**プロポーショナルフォント**なので、`TweetComposer` の `PadRight`（`teamNamePadding` = 12桁）による空白揃えは閲覧側では揃って見えない（チーム名ごとに文字幅が違うため）。空白の分だけ文字数を消費するだけになっている。

対案: 区切り文字ベースの1行フォーマットにする。

```
1. Yankees 52-30
2. Red Sox 48-34 (4.0)
3. Blue Jays 45-37 (7.0)
```

- `勝-負` をハイフン連結にすると `52 : 30 :` より短く読みやすい
- ゲーム差はカッコ書き、**首位は「-」またはカッコ自体を省略**（現状は首位に `0` が表示されて意味が分かりにくい）
- `GamesBehind` はfloatなので `4.5` のような半端も `ToString("0.#")` で `4.5`、整数は `4` と整形する

## 2. 各ツイートのヘッダに日付を入れる

現状の文面には日付が含まれないため、試合がない日など順位が前日から変わらない日は本文が前日と完全一致し、X APIの重複コンテンツ判定（403）でその地区のツイートが失敗する。

対案: 各地区ツイートの1行目に日付を入れる。毎日本文が変わるため重複403が構造的に起きなくなり、リポスト等でタイムライン外から見た読者にも「いつ時点の順位か」が伝わる。

```
📅 7/7 ⚾ AL East
1. Yankees 52-30
...
```

注意: 日付はJST基準（`TimeZoneInfo.ConvertTimeFromUtc` + Asia/Tokyo）・カルチャ非依存の固定書式（`yyyy/MM/dd` 等）で生成すること。

## 3. スレッド（リプライチェーン）化

現状は6地区が独立したツイートとして流れ、タイムライン上でバラバラになる。X API v2はリプライ投稿をサポートしているので、1件目（例: AL East）に対して残りをぶら下げると1スレッドで全地区を追える。

実装: `POST /2/tweets` のレスポンスから `data.id` を取得し、次のツイートのリクエストボディに含める。

```json
{ "text": "...", "reply": { "in_reply_to_tweet_id": "前のツイートID" } }
```

現状 `TwitterApiSender.SendAsync` はレスポンスボディを失敗時しか読んでいないため、成功時に `id` をパースして返すよう変更する。

## 4. 使っていないデータの活用

sportsdata.ioのレスポンスには未使用のデータが多い（`TeamStanding` に使用分のみ定義しているため、使うにはプロパティを追加する）。文字数と相談して足す。

| データ | プロパティ | 表示案 |
|---|---|---|
| 勝率 | `Percentage` | `.634` |
| 連勝/連敗 | `Streak` | `W3` / `L2`、3連勝以上なら🔥 |
| 直近10試合 | `LastTenGamesWins/Losses` | `L10: 7-3` |
| 得失点差 | `RunsScored - RunsAgainst` | `+82` |
| ワイルドカード | `WildCardRank` / `WildCardGamesBehind` | 下記の専用ツイート |

例（1チーム1行に収める場合）:

```
1. Yankees 52-30 🔥W4
2. Red Sox 48-34 (4.0) L10:7-3
```

## 5. ワイルドカード順位ツイートの追加

シーズン後半はワイルドカード争いが最大の関心事。`WildCardRank`/`WildCardGamesBehind` を使ってリーグごとに1件追加する（計2ツイート増）。

```
📅 7/7 ⚾ AL Wild Card
1. Red Sox 48-34
2. Mariners 46-36
3. Royals 45-37
---
4. Guardians 44-38 (1.0)
5. Rays 43-39 (2.0)
```

ボーダーライン（3位と4位の間）に区切りを入れると「あと何ゲームでプレーオフ圏か」が一目で分かる。2ツイート/日の追加はコスト約+$0.03/日（$0.015/件）。

## 6. 文字数バジェットの検証をコードに入れる

X の上限は280字（URLなし・英数字ベース）。5チーム分の行 + ヘッダ + ハッシュタグで現状ギリギリのケースがありうる（`NoPlaceLikeHERE` など長い公式タグ + 長いチーム名の組み合わせ）。

- `TweetComposer`（docs/code-improvements.md 項目1で導入予定）側で組み立て後に長さ検証し、超過時はハッシュタグを削る（公式タグ優先で残す）フォールバックを入れる
- 単体テストで全30チームの組み合わせで280字以内を担保する
- 手動確認にはドライラン（`--dry-run` / `DRY_RUN=true`）を使う。出力に各ツイートの文字数が表示される

## 7. 表示の遊び・可読性向上（小ネタ）

- 順位を絵文字にする: `🥇🥈🥉` + `4. 5.`、または首位のみ👑
- 地区ヘッダを `⚾ AL | East ⚾️ Win : Loss : Behind` から分離（凡例行は毎回必要か再考。`52-30` 形式なら凡例なしで直感的に読める）
- 前日からの順位変動: 前日データを保持する仕組み（S3に前回結果JSONを置く等）が必要になるが、`↑1` `↓2` は情報価値が高い
- シーズンオフ（順位データなし）の日は現状何も投稿されない。「シーズン開幕まであとN日」ツイートにする案

## 8. AIによる一言コメントの付与

各地区ツイートの末尾に、Claude API（Haiku）で生成した一言コメントを付ける案。

```
📅 7/7 ⚾ AL East
1. Yankees 52-30 🔥W4
2. Red Sox 48-34 (4.0)
...
ヤンキース4連勝で首位固め。2位レッドソックスとのゲーム差は4に拡大。
#MLB #RepBX #Yankees
```

- 実装: `BotRunner` で順位データ（前日比があればなお良い）をプロンプトに埋め込み、`claude-haiku-4-5` に「日本語で40字以内、事実のみ、絵文字なし」等の制約付きで生成させる
- コスト目安: 1日6〜8ツイート × 数百トークンなので月数円〜数十円レベル
- 失敗時はコメントなしで投稿するフォールバックを入れる（AI呼び出しをツイート成否に影響させない）
- Lambda環境変数に `ANTHROPIC_API_KEY` の追加が必要
